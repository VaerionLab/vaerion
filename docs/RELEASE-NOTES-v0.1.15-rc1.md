# Release Notes — v0.1.15-rc1

Vaerion 0.1.15-rc1 — the one-true-artifact release

**TL;DR** — Phase 61.0 proved the final P0 blocker: the `0.1.14-rc1` artifact on npm and the `0.1.14-rc1` tree of record were two different engines wearing one version. 0.1.15-rc1 ends that class of failure permanently. The canonical lineage now carries the E1010 journal-completeness anchor (previously only the published artifact enforced it), and a permanent artifact-parity system proves SOURCE = BUILD = PACKAGE = DOCUMENTATION before any publish. Publish of this version to npm is Founder-gated (release-train F-5) — until it runs, `vaerion@rc` on the registry still delivers the older 0.1.14-rc1 engine.

**Install** (requires Bun 1.3+):

```sh
# after the Founder-gated publish of 0.1.15-rc1:
npm install -g vaerion@rc
# today, from the tree of record or the signed release set:
git clone <repo> && bun install --frozen-lockfile && bun run packages/vaerion/src/cli/vae.ts --help
```

**What's new**

- **E1010 is now canonical.** The completeness anchor — *a receipt record certifies the prefix immediately before it* — moved from the published line into the tree of record: catalog entry (82 codes), verification logic, recovery re-certification, redacted-export re-certification, and `vae doctor` completeness reporting. A closed journal whose terminal receipt is missing or stale now fails with `E1010` (exit 5) instead of falsely verifying. The Phase 61.0 truncation attack (delete the receipt → `ok: true`) is closed at HEAD.
- **The attack suite ships as tests.** 12 permanent scenarios at `packages/vaerion/tests/security/journal-completeness.test.ts` — tail deletion, re-chained deletion, receipt substitution, receipt-claim edits, plus the lawful-flow compatibility cases (torn-receipt recovery re-certifies; in-flight runs make no completeness claim; redacted exports self-verify).
- **Artifact parity is mechanical.** `tests/integration/artifact-parity.test.ts` pins the 29-command dispatch surface, the 7-template registry, the did-you-mean module, and the absence of dead CLI files; a docs-claim gate proves every command the quickstart teaches exists in the dispatch; `tools/verify-artifact-parity.ts` re-proves parity on a packed tarball. A release that drops commands or templates now fails in CI, not in a stranger's terminal.
- **Version register → `0.1.15-rc1`** across every measured surface (25 register pins, negative sweep clean, RPM changelog appended). The registry/ tree version split that Phase 61.0 documented can never silently recur: the register refuses a version the artifact pipeline has not proven.

**Prove it on your machine** (~60 seconds, no API key — the demo uses the deterministic MockBrain model):

```sh

vae run demo

# the completeness attack, refused:

```
