# Example — The Replay Machine

> A walkthrough, not a fixture: every command below is a real `vae`
> command (`0.1.13-rc1`) run in a scratch workspace. Your digest values
> will differ (they depend on your config fingerprint); the *identity of
> your two builds* will not.

## Purpose

Prove determinism you can hold: the same inputs produce **byte-identical**
`.vxn` bundles, an independent verifier agrees, and a single flipped byte
is refused loudly — with exit 5, content never executed.

## Architecture

| Piece | Role |
|---|---|
| `vae package build` (ADR-0016) | folds the **declared** `package.include` inputs into a bundle: canonical-JSON manifest, zstd at a pinned level, strict ascending entry order, blake3 digest per entry — no wall-clock, no ambient paths |
| `vaerion.lock` | regenerated by every build; the generated seal over config + pins + bundle digest (never hand-edited) |
| `vae package verify` | the **pure check**: digests recomputed, pins compared against `vaerion.yaml` AND `vaerion.lock`, content never executed |
| `vae provenance` | re-derives the evidence from the bytes alone and reports it honestly per check |

## Code

`vae package build` requires a `package:` block. Start from the minimal
template and declare two real inputs the template scaffolds
(`vaerion.yaml`, `docs/overview.md`):

```sh
cd "$(mktemp -d)"
vae init
cat >> vaerion.yaml <<'EOF'
package:
  include:
    - vaerion.yaml
    - docs/overview.md
EOF
```

Build twice and compare:

```sh
vae package build                                   # → .vaerion/package/my-project.vxn + vaerion.lock
vae package build --out second.vxn                  # build it again
sha256sum .vaerion/package/my-project.vxn second.vxn
```

Let the engine judge the artifact:

```sh
vae package verify .vaerion/package/my-project.vxn
vae provenance .vaerion/package/my-project.vxn
```

Then the tamper game — flip ONE byte and watch trust fail loudly:

```sh
cp .vaerion/package/my-project.vxn tampered.vxn
printf 'X' | dd of=tampered.vxn bs=1 seek=200 conv=notrunc 2>/dev/null
vae package verify tampered.vxn; echo "exit=$?"
```

The repo checkout equivalent: `examples/vaerion-demo/` and
`examples/vaerion/demo-workspace/` ship committed `package:` blocks —
copy one and build it in place.

## Verification

Three independent layers, all recomputed from bytes:

1. **Your own hash** — the two `sha256sum` lines match: byte-identical.
2. **The pure check** — `package verify` reports every finding honestly;
   `VERIFIED (0 finding(s))` when the pins and digests hold.
3. **Provenance** — structure, payload digest, entry digests: each check
   listed with its result, `findings: []` when the evidence holds.

The tampered bundle: `NOT VERIFIED`, **exit 5**, with the failing check
named — and the corrupted content is never executed. Evidence fails
loudly, never silently.

## Receipts

The build itself is a journaled run: it closes with a receipt
(`receipt:` / `journal_verified:` in the build output), and the bundle's
blake3 digest is journaled on the spine (`package.built`). One subtlety
worth knowing: each build also writes journal records, and journals carry
timestamps — so their head hashes differ per build. The **bundle** is the
time-free artifact: its bytes are what reproducibility guarantees.
Journals record *that* something happened; bundles prove *what* was
produced.

## Common mistakes

- **No `package:` block** — `vae package build` refuses (`E1600`) with
  the fix in the message. Declare `package.include` first.
- **Expecting identical journals** — only the *bundle* is
  byte-identical; journals legitimately carry wall-clock fields.
- **Hand-editing `vaerion.lock`** — it is generated; a mismatch with
  reality is a hard verify failure (`E2205`). Rebuild to regenerate it.
- **`dd` on the wrong byte** — any byte inside the payload works; if you
  change the manifest instead, the failure mode differs (still refused).
- **Trusting an unverified bundle** — `NOT VERIFIED` means do not import,
  distribute, or execute. There is no "mostly verified".
