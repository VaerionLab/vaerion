# SNAPSHOT AUTHORITY — Constitutional Governance Structure

**Status:** established (Foundation Amendment **F-002**).
**Authority:** Implementation Constitution P-6 (fidelity standard), 9.3
(Snapshot Authority as the canon of "visually identical"), Part IX.
**Supremacy:** this authority governs; it never implements. The Snapshot
Authority *infrastructure* (capture, comparison, enforcement) is implemented at
**Stage 8 — Testing Infrastructure** against the law defined here.

---

## 1. Mandate

The Snapshot Authority is the constitutional organ that defines and preserves
**the fidelity canon**: the ratified reference renderings against which "two
teams, working independently, produce the same product" (P-6) is mechanically
judged. It exists so that visual fidelity is never a matter of opinion,
memory, or taste — it is a comparison against a pinned original.

## 2. Structure

```
constitution/
    snapshot-authority/
        README.md        <- this authority document (governance)
        snapshots/       <- ratified reference renderings (the fidelity canon)
        manifests/       <- pinned digests and integrity records
```

- `snapshots/` — holds ratified snapshot sets: every surface × state × density
  × theme (both chambers) × breakpoint, as required by the Visual Gate
  (Implementation Constitution Part IX; Visual System §11 modes). **Empty at
  establishment.** No snapshots are ratified yet; capture begins at Stage 8
  with the rendering engine's output (Stage 5), never before.
- `manifests/` — holds integrity manifests: pinned digests of canonical
  artifacts. The first ratified manifest is `manifests/canonical-documents.json`
  (Foundation Amendment F-001), which pins the SHA-256 digests of the three
  ratified constitutional documents and is the binding proof that the
  repository transcriptions are identical to the ratified originals.

## 3. Law of Snapshots

1. **Snapshots are ratified, never casual.** A snapshot enters the canon only
   through the governance pathway (Implementation Constitution 11.2–11.3).
   An unratified image in this tree is a violation.
2. **Snapshots are pinned.** Every ratified snapshot's digest is recorded in a
   manifest. Comparison is digest-first: if the candidate artifact's rendering
   does not match the pinned rendering, the gate fails. Divergence without a
   ratified amendment is failure (Constitution 9.3).
3. **Snapshots are never hand-edited.** A changed canon is a new ratification,
   not an edit. Hand alteration of a pinned snapshot is a constitutional
   violation (rule: F-002/SNAPSHOT).
4. **The canon spans every registered mode.** Light chamber, dark chamber,
   print, grayscale, forced colors, export (Visual System §11). A surface
   ratified in one mode only is not ratified.
5. **The canon is consumed, never duplicated.** Gates compare against the
   canon; they do not maintain private copies. Local copies of canon material
   are violations (parallel: Registry ownership, Constitution 2.4).

## 4. What Does Not Belong Here

- Build outputs, coverage reports, or working render dumps — those belong to
  pipeline tooling, never to the constitution tree.
- Design explorations or "candidate" visuals — the constitution tree holds
  ratified law only.
- Documentation renders — documentation is generated by the Stage 10 pipeline
  from constitutional sources, not snapshotted here.

## 5. Verification Commitments

- `manifests/canonical-documents.json` is verified mechanically by
  `bun run vaerion:verify-constitution` (recompute SHA-256 of each pinned
  document; any mismatch is a `ConstitutionalViolationError`, rule
  `F-001/SNAPSHOT`).
- From Stage 8 onward, the Visual Gate verifies candidate renderings against
  `snapshots/` canon the same way: deterministic, digest-based, fail-closed
  (Constitution 9.1 — every check is pass or fail).
