## 1. What the engine has become on this substrate

The TypeScript-on-Bun reference implementation has carried the program far
past its original "skeleton + spine" mandate (ADR-0018 scoped it to MS-0/MS-1
only). At RC-1 it hosts, with all six gates green and coverage floors
mechanically enforced:

- the full constitutional stack: event spine, hash-chained journal (verify /
  replay / recovery / redacted export), blob CAS, receipts, fail-closed
  broker with durable gates and elevation, refusal log;
- the model gateway (4 adapters incl. MockBrain, metering, budgets, breaker,
  secrets boundary, redaction) behind the single sanctioned egress;
- agents, reasoning sessions, workflow DAG engine, eval harness, metrics;
- both surfaces (CLI + loopback daemon) and a wire-parity TypeScript SDK;
- digest-pinned extension host (subprocess, empty-env, broker-bridged);
- reproducible `.vxn` packaging with byte-identical rebuilds;
- an installer pipeline that installs and smokes its own tarball offline.

Nothing here is a promise of portability — it is shipped, gated, measured
behavior on this substrate (309 tests / 2081 expectations / 31 files).

## 2. Measured budget evidence (blueprint §3.2 vs this substrate)

| ID | Budget | Measured (generated) | Verdict |
|---|---|---|---|
| OBJ-Q1 artifact size | ≤ 25 MB | 0.18 MB tarball | **PASS** (100× headroom) |
| OBJ-Q2 cold start | ≤ 60 ms p50 | 81.5 ms p50 · 127.8 ms p95 (n=15, full `vae version` process) | **FAIL** |
| OBJ-Q3 hot-path overhead | < 8 ms p50 / < 25 ms p99 | 113.0 ms p50 · 141.6 ms p99 (n=12, full `run model` incl. process start + per-record fsync) | **FAIL** |
| OBJ-Q4 memory | ≤ 120 MB active / < 45 MB idle daemon | idle 56.7 MB max RSS (n=10) | **FAIL** |
| OBJ-Q5 index throughput | ≥ 12,000 files/min | 113,008 files/min | **PASS** (9.4× headroom) |
| OBJ-Q6 coverage gates | floors enforced | mechanically enforced by the verify gate | **PASS** |
| OBJ-Q7 zero secrets | asserted in fuzz tests | C5 + golden redaction + distribution scan | **PASS** |

Root-cause composition of the three breaches (measured, not excuses):

- **Process start dominates the hot path.** OBJ-Q2 shows the floor cost of
  any Bun CLI invocation is ~70–80 ms in this environment; OBJ-Q3's 113 ms
  p50 is measured on the full process wall time (start + gateway + journal
  fsync). The 8 ms budget was authored for the in-process hot path of a
  long-lived compiled engine.
- **Per-record fsync is a durability law, not an accident.** Every journal
  record fsyncs (crash-safety law, ADR-0006). A batching ADR can trade
  durability windows for throughput; that is a *design decision with its own
  ADR*, not a silent tuning.
- **Idle RSS 56.7 MB vs 45 MB** is the Bun runtime floor for the daemon's
  feature surface (HTTP/SSE listener + engine + provider registry).

## 3. Production constraints (what GA actually ships)

- Vaerion is a **local-first, single-operator engine**: the daemon is
  loopback-only (ADR-0010), there is no server fleet, no multi-tenant
  hot path, and zero telemetry. The budgets missed are exactly the ones that
  matter for a network edge service; they are the least relevant to a
  developer's local agent runner.
- **Durability beats latency** for the audit chains this project exists to
  provide: replay and receipts are the product.
- **Distribution**: the RC ships as a source checkout + a verified tarball
  (`scripts/dist-pack.ts`); no native binaries are promised for GA. The
  single-static-binary goal belongs to whichever substrate the Founder
  ratifies for *distribution*, and can be pursued after GA without breaking
  contracts.

| **C. Hybrid: ratify for GA, charter the re-platform as MS-GA+1** | Option A now + a ratified roadmap line that ports the journal/spine kernel first (the highest-fanout, most budget-sensitive layer) with goldens as acceptance vectors | Two substrates temporarily (tooling/review cost ADR-0018 already flags) |

**Recommendation (advisory — Founder decides):** Option A at GA, with the
re-baselining ADR recording *why* the original budgets no longer measure the
shipped product's promise, and with Option C's kernel port chartered as the
first post-GA milestone if binary distribution becomes a requirement.
Ratifying before GA keeps every shipped claim gate-proven; re-platforming
under GA pressure would trade verified honesty for aspiration.
